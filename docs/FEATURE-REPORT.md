# Vyro Web — Feature Report (honest)

**Round 2 (review / fix / polish):** build `npm run build` ✅ passes (tsc + Vite, 376 modules). Tests: `npm test` ✅ **33/33** (entitlement 8, store 3, store regressions 9, dir 4, templates 4, i18n 5). Round 1 was 19/19.
**Android project and all Supabase projects were not touched in either round.**

## Round 2 — bugs found in the full audit and FIXED
1. **Last-keystrokes data loss (autosave race):** edits inside the 500 ms debounce window were lost if the user clicked Dashboard / switched documents before the timer fired. → Editor now keeps the pending JSON in a ref and **flushes on unmount, on Back, and on Save now**; the save callback is read through a ref so a stale closure can never write one document's content into another.
2. **Corrupt / malformed localStorage could crash or silently wipe the library:** `loadDocs` returned any parsed array unchecked — an entry without a string `title` crashed search/render. → New `sanitizeDoc` validation/repair on load (bad entries dropped, defaults restored). Unparseable JSON is now **preserved under `vyro-web-docs-v1.corrupt-backup`** instead of being silently overwritten by the next save.
3. **Storage-quota crashes:** `saveDocs` let `QuotaExceededError` (easy to hit with embedded data-URL images) throw inside a React effect. → `saveDocs` never throws, returns success/failure, and the app shows a persistent **save-failure toast** advising an immediate export.
4. **Duplicate shared mutable content:** `duplicateDoc` shallow-copied the TipTap JSON, so the copy and original referenced the same objects. → Content is deep-copied on duplicate and on create.
5. **HTML-export title injection (XSS in the exported file):** the document title was interpolated unescaped into `<title>…</title>` of exported HTML — a title containing `</title><script>…` broke out. → Title (and TOC entries, and imported plain text) now go through `escapeHtml` (`&` first, plus `<`, `>`, `"`).
6. **Unsafe link URLs:** the Link prompt accepted any string, so `javascript:`/`data:` URLs could be stored and exported. → `isSafeLinkUrl` gate: only `http:`, `https:`, `mailto:` are accepted; anything else shows an error toast and sets nothing.
7. **DOCX import mis-detect:** extension check was case-sensitive — `FILE.DOCX` was read as plain text; *any* other file type was silently treated as TXT. → Case-insensitive `.docx`/`.txt` matching; unsupported types fail with a clear toast (import errors already surfaced, now also for these cases).
8. **TXT import escaping incomplete:** only `<` was escaped, so literal `&lt;`-style text was reinterpreted as entities. → Full `escapeHtml` before `<br>` conversion.
9. **Unvalidated image insert:** any file (any type/size) chosen via the file dialog became a data-URL image, and oversized files guaranteed quota loss. → MIME must start with `image/`, size capped at 2 MB, failures shown as toasts; `FileReader` errors surface too.
10. **Inconsistent dashboard mutations:** favorite/rename/duplicate/delete used stale render-time `docs` in some handlers and bypassed the store in others (e.g. inline favorite toggle didn't update `updatedAt`, unlike the store version). → All card actions now use the pure store functions with functional `setDocs(prev => …)` updates.
11. **Dari/Persian search misses:** search did exact matching, so titles typed with an Arabic keyboard (ك/ي) were not found by Persian spellings (ک/ی) and vice versa. → `normalizeSearchText` normalises ك→ک, ي→ی, ة→ه, ؤ→و, أ/إ→ا and strips Arabic diacritics on both sides of the comparison.
12. **Print gaps:** a page-break printed as a dashed rule but did not break the page; landscape documents still printed on portrait A4. → In print CSS the page-break now uses `break-after: page` (marker hidden), and the page uses named `@page` rules (`A4 portrait` / `A4 landscape`) matching document orientation. Status bar and toasts are excluded from print.
13. **Weak document ids:** `uid()` was 8 base-36 random chars + timestamp. → Uses `crypto.randomUUID()` when available, with a longer random fallback.

## Round 2 — audited and found CLEAN (no change made, none invented)
- **Premium-flag trust:** grep + code read — entitlement comes only from `computeEntitlement(fresh supabase.auth.getUser())`; the only `localStorage` keys read are documents (`vyro-web-docs-v1`), theme and UI language. No browser-supplied premium flag is read anywhere.
- **Secrets:** no `service_role`, tokens or project keys in `src/` or `index.html`; Supabase client is created solely from the two `VITE_` publishable env vars (`.env.example` placeholders only).
- **Raw-HTML injection:** no `dangerouslySetInnerHTML` / `innerHTML` anywhere. Mammoth's HTML enters only through TipTap `setContent`, which parses it against the editor schema (unknown nodes/marks are dropped) — that was already the design and remains so. Exported HTML bodies come from `editor.getHTML()` (schema-generated).
- **Template integrity:** all 7 templates produce valid TipTap JSON and pass the existing integrity tests; Dari RTL template direction is correct.
- **Editor doc switching:** `useEditor` is keyed on `doc.id`, and the flush fix in item 1 removed the one real cross-document hazard found.
- **Entitlement rule:** matches Android Model A (strict boolean, `premium_until` semantics) — unchanged, still covered by its 8 tests.

## Incomplete / unsupported (not faked)
- **True pagination:** TipTap has no paginated editing; editing is a continuous A4 page with visual page-break markers. Print output paginates via the browser.
- **DOCX fidelity:** import (mammoth) and export (`docx`) are basic-level — complex Word features (track changes, headers/footers, styles, nested tables, RTL runs in DOCX export) are not preserved. Labelled "basic DOCX export" in the UI.
- **PDF:** browser print-to-PDF only; no generated PDF file, no server PDF. Page numbers in print/PDF come from the browser's `@page` margin-box support (Chromium), not from the app.
- **Cloud sync / accounts for documents:** not built (design in ARCHITECTURE-SECURITY.md). Documents are local-browser only; clearing browser data deletes them — export regularly. Corrupt-data backup key (round 2) mitigates parse failures only, not quota or browser-data clearing.
- **Android's 37 Premium features:** only the 3 web gates are implemented; the rest are Android-only for now.
- **References/Review depth:** no citations/bibliography manager, no comments/track-changes, no grammar check (spellcheck is the browser's).
- **Editor chrome translations:** the editor placeholder text and a few browser-native prompts (`prompt()` dialogs) follow the selected UI language where they are ours; the placeholder string is set at editor creation and refreshes when a document is (re)opened.
- **Font size control** is a set-size dropdown that does not reflect the size at the current selection (TipTap attribute read-back not wired) — pre-existing, unchanged.
- **Bundle size:** main chunk ~943 kB (gzip ~292 kB) — TipTap + docx + Supabase; code-splitting is a future task (mammoth is already lazily imported).
- **Not interactively browser-tested:** this round, like round 1, was verified by build + unit tests + code audit only. An interactive browser pass (typing, Dari RTL editing, print preview, FA chrome) is a separate step and is **not** claimed here.
